# Redesign plan

Temporary. Delete this file when the redesign ships.

## Build order

One page per step. Each step builds the components that page needs (DESIGN.md §3), reusing the ones earlier steps built, and checks them against `design/reference/components.html` (or `components-2.html` for prose and search) and the page's screenshots in both themes and both widths. Each step ends with the reviewer and a commit.

1. ~~**Setup.**~~ Done: Astro project and tooling, tokens, font, content collections, base layout (head, header, footer, skip link, page transitions) and `npm run a11y`.
2. ~~**Home.**~~ Done. Intro with the Download CV menu (and the generated `/cv.md`), about, project tiles (the project card's `tile` variant), work experience rows, latest posts, speaking and teaching, education and contact. Components: button, menu button, see-more link, list row, expandable row, project tile, Roleburn illustration (in its tile), metadata line, figure, external-link arrow.
3. ~~**Writing.**~~ Done. Intro with Subscribe, topic chips, posts grouped by year, and the RSS feed behind Subscribe. Components: chip.
4. ~~**Post.**~~ Done. The article with its reading progress bar and the `/writing/<slug>.md` version. Components: back link + Copy page, the post-header metadata line (date, topic link, reading time), the prose (every Markdown element, footnotes with their Notes section, code blocks with the indigo theme, the Note callout and details), easing demo, author footer, previous/next card.
5. ~~**Projects.**~~ Done. Intro and the project card grid (from 640px, the first project spans both columns when the count is odd). Components: project card, project status line (also on the Home tiles) and page intro (shared with Writing), reusing the project illustrations.
6. ~~**Roleburn case study.**~~ Done. The case study page (`/projects/<slug>`) with its hero and the preview morph from Home and Projects. Components: project facts, the Roleburn hero and the figure placeholder, reusing the back link, code block and previous/next card. work-issue and POL funding spreads have placeholder case studies (see "Content still missing").
7. ~~**Home updates.**~~ Done. From the home-redesign handoff. Intro line with the location. Work rows: work mode after the company, first-line alignment of date, company and +/×, spaced en dash in ranges (also Education). "Speaking and teaching" split into Speaking and Teaching, without the Lisbon photo: talks dated by month with photo attachments; the course as a link row with the course rating line and a video preview. Project facts: one fact per row below 640px, label in the 112px column. Content: `site.yaml`, `work.yaml`, `talks.yaml` (split into talks and courses) and the generated `/cv.md`; the talk photos and trailer thumbnail into `src/assets/`, `speaking-lisbon-2023.jpg` replaced by `talk-lisbon-slide.jpg` (also in `prose.mdx`) and deleted. Components: list row attachment (photos, video preview), course rating line.
8. ~~**404.**~~ Done. The page intro with the "404" label above the title, the sentence naming the missing address (filled in by a script), "Try one of these" rows with the path in the date column (hidden on phones), and the report link with the address prefilled in the email. Components: the page intro's label, the list row's `dateOnPhones` option, and the text link (shared with prose links). The host serves `404.html` with a 404 status.
9. ~~**Search.**~~ Done. The search dialog and its header button on every page: grouped results, key hints (12px, keys grouped 4px apart and 8px before their label), the input's padding reset, the empty, no-results and Download CV states (the formats' step: typing selects a format, never filters), only the title and summary searched (matching word starts, every match in accent text at weight 600), topic rows linking to their topic page, and the JSON index built at build time and carried in the dialog's HTML. A native `<dialog>` opened with `showModal()`; the open states are in `scripts/a11y.ts`. Components: search button, search dialog, search row, key hint. The CV formats now come from `getCvFormats()`, shared with the Download CV menu.
10. ~~**Image viewer.**~~ Done. The talk photos are buttons that open the viewer on Home: the card from 640px (photo, caption, ‹ › on the photo, key hints), and below it the dark full-screen viewer (‹ ›, position dots, drag down to close, pinch to zoom with Panzoom). Back closes it. On rows too narrow for the date column the photos show full width, several in a sideways strip: the site's one container query, at the row's 436px wrap. The open viewer and the next photo are in `scripts/a11y.ts`. Components: image viewer, key hint group (shared with search); the photo attachment's buttons and strip.
11. ~~**Motion pass.**~~ Done. Motion is consistent by role (DESIGN.md §2.5). The overlays' shared recipe from this step was later replaced by the motion-review and remove-animations handoffs (see step 14): search is instant, the Download CV menu grows in and closes instantly, and the image viewer's photo travels from its thumbnail. The project illustrations' loops use tokens.
12. ~~**Site-wide features.**~~ Done. The sitemap (`@astrojs/sitemap`, without the 404 page), `robots.txt` as an endpoint (every crawler allowed, AI crawlers named), page titles as "{page} · Elías García" (Home: the name alone), JSON-LD (`WebSite` and `Person` on Home with the Porto address, `BlogPosting` on posts, typed with `schema-dts`), share images (Satori and sharp at build time: `/share/site.png` for every page, `/share/writing/<slug>.png` per post, with Open Graph and Twitter tags), and Vercel Web Analytics, only in builds on Vercel. The profile's country is now an ISO code named with `Intl`, and a post's reading time is content (`post.yaml`).
13. ~~**Type and spacing.**~~ Done. From the type-and-spacing and 16px-system handoffs; DESIGN.md §2.2 and §2.3 are the source. One 16px base for everything you read or navigate with (post paragraphs, job bullets, second lines, the header menu, search result titles), with hierarchy from colour and weight; six text sizes (32 · 24 · 20 · 16 · 14 · 12; `--text-meta`, `--text-heading` and `--text-long` removed, `--text-subtitle` and `--text-code` added, the display title 28 on phones; 1.6 for running text). Ten spacing steps (4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 · 80 · 96) and three page-rhythm tokens that step down on phones (`--space-page`, `--space-section` at 80 / 64, `--space-footer`). Page titles 20, section headings 16/500; posts get the new heading sizes and the 16px prose rhythm, and the case study uses it too. The post's Notes and author footer, and the case study's "More projects", sit a fixed 64 below the article. Also from the handoffs: topic pages titled "AI · Writing · Elías García", described "Posts about AI by Elías García", and shorter project summaries for the Home tiles. Kept: our topic switching (the page stays in place; since the motion pass, the posts don't re-enter either). There's no `ch` line-length cap: the 640px column sets the measure (`--measure` goes). The search input at 16px also ends the iOS zoom on focus.
14. **Mobile review.** Go through the site on real phones (iOS Safari and others) and collect what needs fixing. Fixed so far, each to confirm on a real phone:
    - The Download CV menu closes as soon as the page scrolls (it drifted from its button and covered the header). Check it on iOS Safari, and on Android Chrome after a long-press on a menu link (that focuses the link, so a touch scroll keeps the menu open).
    - The header no longer shifts when moving between pages in Safari (the nav drew in the fallback font for a frame): the font is `font-display: fallback`.
    - Motion pass (the motion-review and remove-animations handoffs, DESIGN.md §2.5): search opens and closes instantly, the Download CV menu grows in over 150ms and closes instantly (opened with Enter or Space it appears at once), nothing driven by the keyboard animates, cards no longer lift on hover, underlines fade in, the availability dot pings once and the Roleburn hero runs one cycle (hover replays one). Check that the menu visibly grows in on an iPhone.
    - Opening or closing a photo no longer moves the page when the photo sits under the sticky header (the strip's focus handling scrolled the page).
    - The image viewer's photo travels out of the tapped thumbnail and back into the one on screen (a same-document View Transition), and on phones the photos slide with the finger, a flick is enough, and a drag down carries on down as it fades. A wrap with ‹ › slides the way the button points. The thumbnails and the viewer now use one file per photo, so the framing no longer jumps. Check all of it on an iPhone and an Android phone, that a swipe never also scrolls or zooms the page, and that ‹ really goes back (its touch target used to span the whole button row, under ›).
    - Phones and touch (the mobile-native handoff, DESIGN.md §2.9): no tap flash, hover only on real pointers, text links and list rows dim to 60% while pressed (.7 is fine if it feels heavy, never below .6; rows fade back, links return at once), search's Clear button and crumb press to .97, `100svh` page shell, notch padding, no pull-to-refresh behind search or the viewer, a dark status bar while the phone viewer is open, search keyboard set up. Check on an iPhone (Safari) and an Android phone (Chrome), one of them a few years old, in portrait and once in landscape: the tap flash is gone, each link, row and control responds as the finger lands, text clears the notch in landscape and the viewer's × clears the status bar, dragging the viewer down never refreshes the page, the status bar turns dark in the viewer, and the search keyboard's return key says "Go" with nothing capitalised or autocorrected. On Android, with the keyboard open in search the last result stays above the keyboard, and closing search doesn't move the page. On the iPhone, check that links and rows dim and buttons and cards press (iOS applies `:active` only under a `touchstart` listener; the base layout now registers a passive, empty one).
    - Copy buttons keep their width and crossfade their labels (a failed copy shows "Couldn't copy" and the button grows for it); the viewer's controls, previous/next and the video card press.
    - In a window too short for the Download CV menu (a small phone in landscape), the page scrolls until the menu fits as it opens. Check on a real phone that it scrolls smoothly, that the menu stays open, and that dragging the page during that scroll closes it.
    - Still to check: on Android, Back closes the image viewer once and the next Back leaves the page (Back is a close request there, and the viewer also adds a history entry).
15. **Final pass.** Fixed: Chrome sometimes skipped page transitions ("Transition was aborted because of invalid state. ViewTransition opt-in disabled", no script in the stack). It looks for the new page's `@view-transition` before the linked stylesheet applies, so the opt-in is now inline in the base layout's `<head>`; 56 of 56 test navigations transition, against about half before. Also fixed: the reading progress bar never grew in production builds (the CSS minifier folded `animation-timeline` into the `animation` shorthand, which browsers reject; it's now written as longhands). Checked: every page and open state against its screenshots in both themes and at all three widths (no layout differences; content differences only), the keyboard order and focus rings on every page at 1280 and 390, and the accessibility check against the dev server with the drafts (no issues). Decided and done: a code block whose fence names no language has no header bar, and the Download CV formats in search wrap their description.
16. ~~**Icons from Lucide.**~~ Done. From the icons-lucide, implementer-checks and token-cleanup handoffs; DESIGN.md §2.7 is the source. Every icon is a Lucide icon through `@lucide/astro`, drawn by `Icon.astro` under its Lucide name; the hand-drawn files are gone. `b` and `strong` get 600 as a base style. The designer confirmed search has no talk or external-profile rows, so `mic` and `external-link` aren't in the icon table.

## Notes for the next steps

- MDX files don't import components. Render them with `<Content components={mdxComponents} />` inside `Article` (which sets its content as `Prose`), as the post and case study pages do; `src/components/mdx/index.ts` maps Markdown elements to components and lists the components posts and case studies can use.
- `src/content/writing/prose.mdx` is a draft with every prose element (`/writing/prose` in `npm run dev`). Check it against `design/reference/prose.html` whenever prose or code styles change.
- Reading time: use `getReadingTime(post)` from `src/lib/content.ts`.
- Interface text lives in `src/content/`, one file per part of the site, each with a getter in `src/lib/content.ts` (`getHomeCopy()`, `getLayoutCopy()`…). Addresses come from `routes` in `src/lib/routes.ts`.
- `npm run a11y` checks pages only. Add each interactive state (open menu, open dialog) to `scripts/a11y.ts` in the step that builds it.
- When `src/env.d.ts` is added, allow `interface` there in `eslint.config.ts`.
- TypeScript stays on 6.0 because `@astrojs/check` and `typescript-eslint` don't support 7 yet. Move to 7 once both list it as a supported peer.
- `npm run a11y` runs in the installed Google Chrome (`channel: "chrome"`), so any machine or CI runner that runs it needs Chrome.
- The 404 page has no `noindex`: a real 404 status already keeps it out of search results. If it ever gets one, add `"autodiscoverUrlBlocklist": ["/404.html"]` to `collect` in `lighthouserc.json`, or the SEO check fails.

## Still to do

- **OS text scaling** (`<meta name="text-scale" content="scale">`, Chrome and Edge 146+). Not opted in yet: with the default text size doubled, phone-width layouts break (the header's links run off the side, search rows squeeze their text, the contact email overflows). Desktop widths are fine. Fix those, test every page at 200% and 320px, then add the tag.

## Decided against

- **Cards as `<article>`.** List plus headings already provide the navigation; `<article>` would add a redundant announcement per card with no practical gain.

## Going live

1. Import the repo into Vercel and check the `redesign` preview. Check the response headers there (`curl -I`): `vercel.json` sets them and they can't be tested locally. Open the browser console on the preview too and check for Content-Security-Policy violations: Web Analytics only loads on Vercel, so the policy is untested with it (it loads from the same origin, so it should pass). The policy blocks Vercel's preview toolbar; that only affects previews.
2. Merge `redesign` into `main`, add `eliasgarcia.dev` in Vercel and point DNS at it.
   Turn on Web Analytics in the Vercel project, then visit a missing address from another page and check that the page view records that address and the referrer (the log of broken links). The site uses `inject()` rather than Vercel's Astro component, which records the path known at build time, `/404`.
3. Once the domain serves from Vercel, turn off GitHub Pages and delete the `gh-pages` branch.
